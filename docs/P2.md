==================================================
A. PERFORMANCE — PRIORITY ZERO
==================================================

Текущая реализация BTRemote/TouchpadView.swift использует
UIPanGestureRecognizer -> translation -> HID mouse.

ЭТО НЕДОСТАТОЧНО.

Apple UIKit обычно доставляет обычные touch events около 60 Hz,
но дополнительные hardware touch samples могут быть доступны через:

UIEvent.coalescedTouches(for:)

Нужно определить ФАКТИЧЕСКИЙ pipeline на physical iPad.

Задача:
сделать измеримый high-rate input path.

--------------------------------
A1. METRICS
--------------------------------

Добавить PerformanceMetrics без изменения HID descriptor.

Измерять rolling 1-second windows:

- delivered UIKit event Hz
- raw/coalesced touch samples Hz
- generated relative mouse reports/sec
- attempted BLE mouse reports/sec
- successfully accepted updateValue reports/sec
- BLE backpressure count
- pending/coalesced mouse count
- dropped/lost relative delta if any
- average input sample interval
- max sample interval / jitter

Debug overlay скрыт по умолчанию.

В developer mode показывать примерно:

Touch event:     60 Hz
Raw samples:    120 Hz
Mouse generated:118 Hz
BLE accepted:   115 Hz
Backpressure:     3/s
Lost delta:       0
Avg interval:   8.4 ms
Max interval:  17.0 ms

НЕ выдумывать значения.
Они должны считаться из runtime counters.

--------------------------------
A2. HIGH FIDELITY GAME INPUT
--------------------------------

GAME mode НЕ должен использовать только обычный UIPanGestureRecognizer
как источник movement samples.

Исследовать и реализовать отдельный high-fidelity input surface,
скорее всего UIView / custom touch handling:

touchesBegan
touchesMoved(_:with:)
touchesEnded

В touchesMoved использовать:

event.coalescedTouches(for: touch)

и обрабатывать ВСЕ реальные samples в хронологическом порядке.

Для каждого sample считать delta относительно предыдущего ACTUAL sample.

НЕ использовать predictedTouches для HID mouse movement.
Predicted touches могут дать ложный aim.

TRACKPAD gesture UX может остаться gesture-recognizer based,
но GAME должен иметь raw/high-fidelity path.

--------------------------------
A3. BLE TRANSPORT
--------------------------------

Посмотреть BTRemote/LowEnergy/HIDPeripheral.swift.

Сейчас updateValue() при backpressure имеет один:

pendingBroadcast: (Data, characteristic)

Для relative mouse это потенциально опасно:
следующий relative report может заменить предыдущий,
а relative delta нельзя просто терять.

НЕ делать generic giant queue.

Для mouse reports определить минимальный корректный механизм:

если BLE temporarily not ready:
- аккумулировать relative dX/dY;
- clamp/split при отправке;
- сохранить button state;
- НЕ терять суммарное движение;
- drain после peripheralManagerIsReady.

Keyboard/consumer semantics не ломать.

Добавить counters для:
accepted / backpressured / coalesced.

--------------------------------
A4. CONNECTION LATENCY
--------------------------------

Исследовать:

CBPeripheralManager.setDesiredConnectionLatency(.low, for: central)

Когда central реально известен/subscribed:
запросить LOW latency там, где это корректно.

Не считать request гарантией.
Просто request + metrics.

Не менять pairing/HOGP descriptors.

A5. PHYSICAL PERFORMANCE BUILD
--------------------------------

Собрать отдельный physical-test-ready IPA РАНЬШЕ остальных фич.
