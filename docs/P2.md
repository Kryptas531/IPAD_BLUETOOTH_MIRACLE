## Что реализовано (факт по текущему main, проверено чтением кода)

### A1. PerformanceMetrics — IMPLEMENTED
`BTRemote/PerformanceMetrics.swift` — rolling one-second окна: delivered UIKit
touch Hz, raw/coalesced samples Hz, generated mouse reports/sec, attempted BLE
reports/sec, accepted `updateValue` reports/sec, backpressure count,
pending/coalesced count, lost delta, avg/max sample interval (+jitter).
Значения считаются из runtime-счётчиков, не выдуманы. Overlay скрыт по
умолчанию, показывается в developer mode (`BTRemote/TrackpadPanel.swift`).

### A2. GAME high-fidelity input — IMPLEMENTED
`BTRemote/TouchpadView.swift`: `touchesBegan` / `touchesMoved(_:with:)` /
`touchesEnded` + `UIEvent.coalescedTouches(for:)` (TouchpadView.swift:222);
все реальные samples обрабатываются в хронологическом порядке, delta считается
от предыдущего ACTUAL sample; predicted touches для HID mouse movement НЕ
используются. TRACKPAD остался gesture-based (UIPanGestureRecognizer) — как и
допускала постановка.

### A3. BLE mouse backpressure — IMPLEMENTED
`BTRemote/LowEnergy/HIDPeripheral.swift`: при temporary BLE not ready
аккумулируются `pendingMouseDX/DY/Wheel` (:52, :118); clamp/split через
`mouseChunk` при отправке (:400); button state сохраняется; суммарное движение
не теряется; `drainPendingMouse()` после `peripheralManagerIsReady`
(:382, :582). Keyboard/consumer semantics не сломаны. Counter'ы
accepted/backpressured/coalesced — в PerformanceMetrics. Fix `5e8f52e`:
`PerformanceMetrics.recordLostDelta` теперь принимает `Int32` (вызов
`recordLostDelta` в `HIDPeripheral.swift:387` — внутри защищённого стека —
не меняли).

### A4. Connection latency — IMPLEMENTED
`CBPeripheralManager.setDesiredConnectionLatency(.low, for: central)` —
`HIDPeripheral.swift:542` (request + metrics; request не есть гарантия).

### A5. Physical performance build — IMPLEMENTED, MEASURED
physical-test-ready IPA собран (green CI run `35511332912`, artifact
`btr-remote-unsigned-ipa`, скачан через gh в `.qwen/tmp/ipa-p3/BTRemote.ipa`).
Пользователь установил его и снял реальные значения (MEASURED, см. «MEASURED
FACTS» в `QWEN.md`): iPad touch events ~40-60 Hz; raw/coalesced samples до
~120 Hz; хороший прогон: ~120 raw samples, ~128 BLE accepted, lost delta = 0,
raw sample interval ~8.3 ms; Windows Raw Input для BTRemote: p50 ~14.8-14.9 ms,
negotiated BLE interval 15.0 ms, latency 0, timeout 2000 ms, PHY LE 2M;
control ROG CHAKRAM X over Bluetooth: baseline interval 7.5 ms → Windows и
текущий BT controller умеют 7.5 ms.

### B. UX/LAYOUT — IMPLEMENTED (polish — PLANNED)
Windows-first UI: GAME | TRACKPAD | TOUCH | DECK (TOUCH — EXPERIMENTAL, в
разработке). Доминирующий input surface: без permanent scroll column и
permanent L/M/R row; без больших CONNECTED / DIRECT INPUT / debug /
setup-status панелей (статусы — компактные индикаторы). Windows keys:
Ctrl / Win / Alt / Shift (не Command/Option); extended keys только overlay;
keyboard overlay (`BTRemote/KeyboardView.swift`). Direct Input: физическая
Windows-клавиатура через iPad (`BTRemote/DirectInputController.swift`,
release chord `Ctrl + Alt + Backspace`, configurable; страховочная кнопка
Release Direct Input — в temporary/extended зоне, не занимает main area).
DECK: Windows shortcuts + navigation + F1-F12 (страница 2, grid;
`BTRemote/RemoteView.swift`). TV remote удалён из product direction
(`BTRemote/DPadView.swift` — legacy, не используется).
